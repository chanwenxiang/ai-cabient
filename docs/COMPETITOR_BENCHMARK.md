### CB-001 消费者准入：不用独立实名前置，靠支付分/信用分门槛

- **竞品做法**：
  - **友宝 UBOX**：与支付宝合作刷脸开门（「一刷、二开、三结算」），**刷脸即身份核验**，商家不另索取身份证；风控用**芝麻信用准入 + 动态风控**，官方案例称资损率从 **2% 降至 0.1%**。
  - **微信支付分**（⭕ 官方）：「智慧零售」场景**明确适用无人零售机柜** —— 分数达商户设定门槛才可开柜；商户获免密代扣 + **催收**能力；平台按行业场景设**订单风险金上限**（单次可发起免密代扣的最高额）。
  - **支付宝芝麻先享**（⭕ 官方）：商家平台文档在风控参数中**专门列出智能货柜场景**（`credit_allpass`）；官方另说明**未开通支付分/未实名的用户没有先享后付、无法使用开门柜**。
- **对照主体**：友宝 UBOX ｜ 微信支付分（官方）｜ 支付宝芝麻先享（官方）｜ 美智微
- **证据**：

  - <https://news.iresearch.cn/content/2019/06/292737.shtml> （🟡 友宝副总裁 · 芝麻信用准入 + 动态风控）

  - <https://m.sohu.com/a/600752492_121075045> （⚪ 美智微 · 未实名/低信用用户直接不可用）

- **我们的结论**：**采纳「不把实名作为开门前置」**（2026-10-06 决策），现获**双通道官方源**佐证。
    
  准入走「微信/支付宝侧信用与免密能力 + 平台侧风控事件」。但**手机号必须有**（催缴/追溯唯一可靠通道，见 CB-003）。
    
  🔴 **但我们当前无法真正落地**：微信支付分 `NOT_IMPLEMENTED`、支付宝代扣未配置（落地障碍见 CB-010、CB-011）。

### CB-002 实名不是消费者开门的门槛（独立佐证 CB-001）

- **竞品做法**：
  - **美智微**：微信/支付宝**几乎没用过、甚至没做实名认证**的用户**没有先享后付功能、无法使用开门柜** ⇒ 实名是**支付平台的准入结果**，非商家另设门槛。
  - **友宝 UBOX**：刷脸路径本身就完成身份核验；据其副总裁表述，大额高频&#x4E5F;**「跑单不太担心」**，风控靠信用分模型而非实名。
  - **哈哈零兽**：走**微信/支付宝免密支付**，宣传链路为「扫码开门 → 开通免密支付 → 取货 → 关门自动结算」，**全链路无独立实名环节**。
  - 反例（勿照抄）：老系统 easygo 使用法大大 CA 做 B 端签约，存身份证号/证件照/银行卡 —— 那是**B 端运营商签约**，不是 C 端买饮料。
- **对照主体**：美智微 ｜ 友宝 UBOX ｜ 哈哈零兽 ｜ 微信支付分（官方）
- **证据**：
  - <https://m.sohu.com/a/600752492_121075045> （⚪ 未实名/低信用用户直接不可用）
  - <https://baike.baidu.com/item/%E5%93%88%E5%93%88%E9%9B%B6%E5%85%BD/68233056> （⚪ 哈哈零兽 · 扫码开门→免密支付→关门结算）
  - <https://news.iresearch.cn/content/2019/06/292737.shtml> （🟡 友宝刷脸核验路径）
  - <http://www.cfshj.com/agreement-merchant.html> （⚪ 反例：B 端签约才收身份证）
- **取证日期**：2026-10-07
- **我们的结论**：**采纳，并明确不做**消费者实名开门前置（三家同行均无此环节，非仅一家）。

### CB-003 欠款催缴：平台自动重试 + 短信是唯一可靠通道

- **竞品做法**：
  - **微信支付分**（⭕ 官方）：**商户无需再次发起扣款**，微信会按一定频次**自动重试**免密代扣直到成功；超过一定时间仍未成功，**支付分向用户发送催收消息**。
  - **美智微**（服务商侧实操）：用户**每天都会收到催款短信**，微信/支付宝**每天自动尝试扣款**直到成功；超**三天**未还款或未扣款成功，**支付分/芝麻信用严重降分**，并会收到平台催收。
  - **支付宝芝麻先享**（⭕ 官方）：官方定义了明确的状态机 —— 首次扣款失败 → **2 小时后**转「待守约」；**首次发起 7 天内**扣款成功 → 「已守约」；**7 天后**仍失败 → 「**已逾期**」；逾期后再成功 → 「**逾期后守约**」。且商家阶段具备**智能代扣**，发起一次即自动智能对用户扣款。
- **对照主体**：微信支付分（官方）｜ 支付宝芝麻先享（官方）｜ 美智微 ｜ 友宝 UBOX
- **证据**：
  - <https://pay.weixin.qq.com/doc/v3/partner/4012158690> （⭕ 官方 · 自动重试与催收消息）
  - <https://opendocs.alipay.com/open/0byb4r> （⭕ 官方 · 待守约/已守约/已逾期/逾期后守约状态机与智能代扣）
  - <https://m.sohu.com/a/600752492_121075045> （⚪ 每日短信 + 每日重扣 + 三天降分）
  - <https://www.hkexnews.hk/listedco/listconews/sehk/2026/0428/2026042803198_c.pdf> （🟡 友宝港交所公告 · 与支付宝支付的持续关连交易）
- **取证日期**：2026-10-07
- **我们的结论**：**采纳「短信为催缴主通道」**。理由与竞品一致但更硬：我们现有催缴只走**微信订阅消息**，而订阅消息**需用户主动订阅** ⇒ 最该被催的逃单者恰恰收不到。`user_info` 必有手机号，短信是唯一无条件可达通道。
    
  🔴 **催缴节奏须与官方状态机对齐**：竞品是「小时级重试 + 2 小时转待守约 + 7 天转逾期」，不是无限期重试。升级动作见 CB-004。

✅ **V325 已落地（2026-10-07）**：`UnpaidDunningService` + 催缴模板 `unpaid_order_dunning`（`channels` 含 `SMS`）。
  
关键发现：短信链路**早已存在**（`ExternalNotificationDispatcher.sendSms` + `WebhookSmsSender.sendMessage`），
  
缺的只是「模板 channels 没含 SMS」—— 即模板才是决定性开关，不是可选项。
  
自动催缴并入既有 `unpaid-cancel` 调度（**不新增** `@Scheduled`）：
  
① `SchedulingPoolCapacitySelfCheck` 判「@Scheduled 并发 ≤ Hikari 池」，实测加一个就 8 > 5 报风险；
  
② 催缴必须在关单**之前**，订单一旦 CANCELLED 就没有可缴对象了。

### CB-004 追缴升级路径：先催 → 降信用分 → 设备/平台级拉黑（不是全平台）

- **竞品做法**：
  - **宇脉电子**：关门结算出现**订单负数**且用户**不补回**，后台可**拉黑名单，该用户不能再使用该设备**；支付分模式下连续一个月确实没钱支付，会**降低支付分或拉黑该微信**。
  - **美智微**：可把顾客**拉入黑名单，以后无法使用任何美的智能机器**（厂商级）；并提到报警后警方会电话追缴。
  - **微信支付分**（⭕ 官方）：**恶意用户计入超时支付记录，同行业或跨行业联合惩戒机制**完善催收能力。
  - **哈啰出行**（跨行业合规红线）：非持牌主体**不能自行报送征信**，普通骑行未付费**大概率不会上征信**；只有「合作金融机构提供的信贷服务」违约才可能触发报送，且需**事先取得信息主体书面同意**。企业**无权司法认定、无权单方拉黑**。
  - **同行侧对照**：**宇脉电子**在订单出现负数且用户不补回时，后台可直接**拉黑名单、该用户不能再使用该设备**（见 CB-004）；**美智微**后台可查看订单手机号与全程录像、并**自行发送账单要求付款**，必要时解锁机器（见 CB-012）⇒ 同行的「自助追缴」能力**止于平台内提醒与限制**，与哈啰/征信边界一致。
  - **同行侧对照**：**宇脉电子**在订单出现负数且用户不补回时，后台可直接**拉黑名单、该用户不能再使用该设备**（见 CB-004）；**美智微**后台可查看订单手机号与全程录像、并**自行发送账单要求付款**，必要时解锁机器（见 CB-012）⇒ 同行的「自助追缴」能力**止于平台内提醒与限制**，与哈啰/征信边界一致。
  - 法律侧：人民网云南普法区分「无心之失」与「故意逃单」，先沟通留记录、必要时报警；**不可限制人身自由、暴力索款、曝光隐私**。
- **对照主体**：宇脉电子 ｜ 美智微 ｜ 微信支付分（官方）｜ 哈啰出行（合规范式）
- **证据**：
  - <https://gdymdz.com/article_show-1045-view.html> （⚪ 设备级拉黑）
  - <https://m.sohu.com/a/600752492_121075045> （⚪ 厂商级拉黑 + 报警追缴）
  - <https://pay.weixin.qq.com/doc/v3/partner/4012158690> （⭕ 官方 · 超时支付记录与跨行业联合惩戒）
  - <https://www.jiwenlaw.com/n/8LSDEUGIA4VA.html> （⚪ 哈啰 · 征信报送边界与「无权单方拉黑」）
  - <https://yn.people.com.cn/BIG5/n2/2025/0611/c361322-41255870.html> （🟡 官方法治口径 · 维权红线）

### CB-005 「预冻结」的竞品等价物是**保证金/负余额**，不是资金冻结

- **竞品做法**：
  - **宇脉电子**（称重柜，未开通支付分时）：**扫码支付保证金 → 开门 → 取货 → 关门结算**；若商品总额超过保证金，**订单出现负数**，再次使用前**必须补回才能再使用**。
  - **美智微**：微信/支付宝会扣所有绑定卡、信用卡、花呗；**全部无余额则扣款失败**，订单留在后台，店主可查看手机号与全程录像并**每天自动重扣 + 每天催款短信**。
  - **微信支付分**（⭕ 官方）：风险金（`risk_fund`）有「先免 / 先享」两种模式 —— **先免**（押金 `DEPOSIT` / 预付款 / 保证金 `CASH_DEPOSIT`，评估不通过可交押金继续用）；**先享**（预估订单费用 `ESTIMATE_ORDER_COST`，**评估不通过则创单失败、不可使用服务**）。
- **对照主体**：宇脉电子 ｜ 美智微 ｜ 微信支付分（官方）
- **证据**：
  - <https://gdymdz.com/article_show-1045-view.html> （⚪ 保证金 + 负余额 + 补回才能再用）
  - <https://m.sohu.com/a/600752492_121075045> （⚪ 多渠道自动扣款失败后的处置）
  - <https://pay.weixin.qq.com/doc/v3/merchant/4012164158> （⭕ 官方 · 先免/先享模式与 risk_fund 取值）
- **取证日期**：2026-10-07
- **我们的结论**：**采纳「欠款即负余额 + 补回才能再用」模型**，作为我们「预冻结/风险控制」的实现形态。
    
  即：不真去冻结用户资金（我们无资金冻结资质，且预付资金池有合规成本），而是**欠款用户限制再次开门**，用**行为限制**替代**资金冻结**。这是用户所提「预冻结」在 C 端无牌照下的正确落地形态。
    
  ⚠️ 官方「先享模式」给了更硬的依据：**评估不通过就直接不可用**，比「先开了再说」更省资损，值得作为我们额度策略的参考。

### CB-006 识别方案：视觉替代称重是行业确定性趋势，过渡期两轨并存是经济理性

- **竞品做法 / 行业数据**：
  - **哈哈零兽**（同为视觉路线）：核心技术是「**静态视觉剩余识别**」—— 每层摄像头，开门时拍全柜、关门后再拍，用**前后库存做减法**判断拿了什么；官方运营测试称识别率 **>99%**、可识别 **1000–30000 种**商品；⚠️ 但其自身说&#x660E;**「商品相互遮挡叠放、外观极其相似时准确率会受影响」** ⇒ **99% 是实验室/运营测试口径，不是全场景保证**。
  - **丰e足食**（18.4 万台纯直营）：用「**封闭式柜门 + AI 视觉识别**」解决信任成本，**货损率降到接近于零**；每柜平均陈列 **48 个库存单位**、每月引入 **7.3 个新品**；**单柜月销约 1200 元 / 单日约 40 元**，**单柜月销 300 元即达点位盈亏平衡**。
  - **友宝 UBOX**：单台货柜**月销约 3316 元**（重场景高客流，约为丰e轻场景的 3 倍，但租金与资源成本更高）。

### CB-012 【新】行业踩坑：视觉误识与免密都有真实投诉，我们该防什么

- **竞品做法（反面案例）**：
  - **哈哈零兽**公开投诉记录（2022）：有用户在江汉大学使用其零售柜后被**无故重复扣款 4.5 元**且退款被拒；另有用户投诉通过**支付宝免密支付「私自扣款非本人操作」（3 元）**，且扣款后**单方面解除了免密支付协议**。
  - **美智微**公示能力：店主可查看**每笔订单顾客手机号 + 顾客使用机器的全过程录像**，并可自行**发送账单要求付款**、必要时解锁机器。
  - **行业研究**（🟡 中研普华转载）：明确列出「**货损与识别风险，技术无法完全杜绝漏付、误识别**」—— 视觉方案受**商品遮挡、光线变化**影响导致漏付/错扣；「**误扣款、扫码失败、卡货**等问题，缺少现场店员即时处理，售后投诉处理成本高」；「货损率一旦超过阈值，直接击穿单品利润」。
  - ⚠️ **具体失效场景**（⚪ 行业自媒体，**数据未独立核实，但场景具体可复现**）：商品**倾斜 30 度以上**识别率下降 15–20%；不规则摆放使某点位货损从 1.8% 升到 **7.3%**；**LED 大屏反射**使识别率掉到 73%–78%；**包装改版**（元气森林换新包装）导致 5 个城市识别失败两周、损失近 8 万；**多人并发**场景货损是单人场景的 **4–6 倍**。
- **对照主体**：哈哈零兽 ｜ 美智微 ｜ 中研普华（行业研究）
- **证据**：
  - <https://baike.baidu.com/item/%E6%AD%A6%E6%B1%89%E5%B8%82%E5%93%88%E5%93%88%E4%BE%BF%E5%88%A9%E7%A7%91%E6%9C%89%E9%99%90%E5%85%AC%E5%8F%B8/22434035> （⚪ 百度百科 · 社会事件：重复扣款/私自扣款投诉）

  - <https://www.dozzon.com/insight-ai-vision-cabinet-99.html> （⚪ 具体失效场景：倾斜/大屏反射/包装改版/多人并发）

- **我们的结论**：**采纳为四条设计要求**（与 CB-005「先享模式：评估不通过即不可用」呼应）：
  1. **扣款必须幂等且可解释**：同一订单不得重复扣款（同行已因此被公开投诉）。
  2. **免密协议不得单方面解除**；用户对扣款有异议时必须有**人工可查的申诉通道**。
  3. 🔴 **视觉必须有异常订单人工复核兜底**：识别不确定时**宁可挂起等人工确认，不要直接扣款**。因为误识 + 自动扣款 = 投诉 + 退款成本 + 监管风险（行业已明确点出「缺少现场店员即时处理，售后投诉处理成本高」）。
  4. ⚠️ **陈列规范是技术要求，不是运营细节**：同行案例显示**商品倾斜 30° / 不规则摆放 / 包装改版**都能让识别率崩掉 ⇒ 补货必须遵守摆放角度与层高规范，且**包装改版要触发模型重训**，否则会出现大面积错扣。
       
     ⇒ 这条直接约束「视觉识别 + 免密代扣」的组合设计：**异常订单必须留人工决策位**。

  - **友宝 UBOX**：刷脸开门（「一刷、二开、三结算」）—— 核身由**支付宝侧**完成，商家不索取证件。

     依据不只是「同行没做」，更是**官方协议 2.3**：平台只给「能不能用」，

  5. 🚫 **不要**再往前一步做「免实名通道」：平台侧实名是强制的，
