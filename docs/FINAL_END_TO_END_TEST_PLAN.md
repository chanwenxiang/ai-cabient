# AI 开门柜最终版全链路测试计划

版本：1.0  
适用阶段：开发联调、预发布、单点灰度、正式上线验收  
适用产品：消费者微信小程序、商户/补货微信小程序、运营管理后台、柜机 Android 端、交易服务、设备服务、视觉服务及基础设施

## 1. 测试目标

本计划验证的不是“页面可以打开”或“一次购物能够成功”，而是验证系统从基础资料、采购、仓储、配送、补货、消费者购物、识别结算、资金账本、库存、售后、商户结算到运营异常的完整闭环。

最终系统应同时满足：

1. 正常业务可以完成。
2. 异常业务可以恢复、取消或转人工处理。
3. 重复请求、并发请求、消息乱序不会产生重复订单、重复扣款或重复库存。
4. 任意资金和库存变化均可追踪、可对账、可审计。
5. 三个正式前端与柜机端状态一致，界面达到商业产品的可用性和审美要求。
6. 商户、补货员、运营、财务和消费者之间的数据与权限严格隔离。
7. 模拟环境验证通过不等同于真实支付、真实硬件和真实视觉识别通过；上线前必须完成真机专项验收。

## 2. 正式产品边界

| 端或服务 | 正式职责 | 测试重点 |
|---|---|---|
| `clients/consumer-mp` | 消费者微信小程序 | 登录、扫码、开门、会话恢复、账单、余额、申诉、报修 |
| `clients/merchant-mp` | 商户/补货微信小程序 | 经营概览、柜机、要货、补货、库存、任务、异常 |
| `clients/admin-vue` | 运营管理后台 | 设备、订单、异常、争议、采购、仓储、补货、资金、对账、权限 |
| `edge/android-app` | 柜机 Android 工控端 | 门锁、摄像头、传感器、心跳、离线缓存、事件补传 |
| `services/trade-service` | 交易与业务真相来源 | 会话、订单、资金、库存、异常、商户与运营 API |
| `services/device-service` | 设备接入与命令 | MQTT、指令、ACK、在线状态、重试和超时 |
| `vision-service` | 商品识别 | 视频接收、模型推理、识别结果、置信度和失败降级 |
| `edge/device-simulator` | 开发测试模拟器 | 模拟开关门、购物时长、重力变化和多商品选择 |

消费者和商户 H5 仅作为浏览器自动化测试壳，不作为正式 Web 产品验收。

## 3. 测试原则

- 服务端状态是会话、订单、余额和库存的最终真相来源。
- 每条主流程必须同时具备正常、失败、超时、重复、并发、恢复和权限测试。
- 每个危险操作必须验证二次确认、权限、审计和幂等。
- 每个页面必须验证加载、空数据、错误、无权限、失效和成功状态。
- 每个缺陷修复后必须执行原用例、相邻业务用例和回归用例。
- 测试报告必须保留请求数据、响应、数据库证据、日志、截图和资金/库存前后值。
- 不允许用手工修改数据库代替正常业务流程；仅允许在准备隔离测试数据时使用种子脚本。

- 补货员 A、补货员 B、仓库员、采购员。
- 普通运营、异常专员、客服、财务、超级管理员。

- 在线柜机、离线柜机、维护柜机、占用柜机、禁用柜机。

- 正常 SKU、禁售 SKU、缺映射 SKU、临期 SKU、过期 SKU。
- 正常供应商、停用供应商；正常仓库和禁用仓库。
- 单商品、多商品、同 SKU 多件、取出后放回的识别样本。

## 5. 全业务逻辑和测试用例

## 5.1 基础资料与系统配置

### 正常逻辑

1. 创建或维护商户、柜机、货道、SKU、价格、供应商、仓库和角色。
2. 建立柜机与商户、货道与 SKU、视觉类别与 SKU 的映射。
3. 配置最低开门余额、会话超时、临期阈值、异常 SLA 和商户权限。

### 边界与异常

- 重复设备 ID、SKU ID、供应商 ID、仓库 ID。
- 空名称、超长名称、特殊字符、Emoji、前后空格和中文回显。
- 无效价格、负价格、零价格、超大金额和超过货道容量。
- 停用 SKU 仍存在库存或活动订单。
- 删除仍被采购单、订单、库存或批次引用的数据。
- 同一货道绑定多个有效 SKU。
- 同一设备跨商户绑定。
- 配置修改过程中的并发覆盖和版本冲突。
- 配置修改后的缓存刷新、服务重启和多实例一致性。

### 验收

- 所有核心 ID 唯一；关键引用不能产生孤儿数据。
- 修改前后有审计记录。
- 中文字段在 API、数据库、页面和导出中不出现 `????`。

## 5.2 供应商、采购和采购收货

### 正常逻辑

1. 采购员维护供应商。
2. 创建包含一个或多个 SKU 的采购单。
3. 仓库按采购单分批收货并执行质检。
4. 合格商品按批次、成本、生产日期和到期日期入库。
5. 采购单从 `CREATED` 转为 `PARTIAL_RECEIVED`，最终转为 `RECEIVED`。

### 边界与异常

- 停用或不存在的供应商创建采购单。
- 不存在或禁售 SKU、空明细、重复 SKU 行。
- 数量为 0、负数、超大数量；成本为负数或精度越界。
- 不存在或停用仓库。
- 收货数量超过剩余采购数量。
- 重复提交相同收货请求。
- 一部分质检合格、一部分不合格。
- 全部拒收、短收、多批次收货和跨日收货。
- 采购单已完成后再次收货。
- 收货过程中服务异常或数据库事务回滚。
- 采购退货、供应商退换货和冲销能力检查；若产品未实现，列为上线前缺口。

### 一致性检查

- 采购单累计收货数量等于批次入库数量。
- 入库数量、仓库库存和库存流水一致。
- 同一幂等请求不得重复增加仓库库存。

## 5.3 仓库入库、库存、出库和在途

### 正常逻辑

1. 查看仓库库存、批次和流水。
2. 根据补货路线创建出库单。
3. 仓库拣货并确认商品、批次和数量。
4. 出库单发运，库存由仓库库存转为在途库存。
5. 柜机补货签收后，在途库存转入柜机库存。

### 边界与异常

- 无采购来源的手工入库必须记录原因、来源和操作人。
- 仓库库存不足时出库。
- 同一批次并发出库造成超卖。
- 未拣货直接发运。
- 重复拣货、重复发运、已发运取消。
- 一张出库单包含多设备、多 SKU、多批次。
- 部分设备签收、部分未签收。
- 在途短少、破损、丢失、拒收、退回仓库。
- 发运后补货员长期未领取。
- 服务重启后在途状态恢复。
- 出库与补货任务生成之间部分失败。

### 一致性检查

任一时刻必须满足：

`采购累计入库 - 退货 - 报损 = 仓库库存 + 在途库存 + 柜机库存 + 已销售数量 + 其他有审计的调整`

## 5.4 商户要货、补货路线和现场补货

### 正常逻辑

1. 商户查看低库存和系统建议。
2. 商户提交要货申请。
3. 运营接单或驳回。
4. 系统生成补货路线、出库单和任务。
5. 补货员在小程序查看自己的任务并到柜签到。
6. 补货员按货道录入实补、下架和异常数量。
7. 完成任务，生成柜机库存快照和差异记录。

### 边界与异常

- 商户操作非所属柜机。
- 要货数量为 0、负数、超过容量或重复 SKU。
- 相同申请连续提交。
- 已接单申请再次接单或驳回。
- 补货员查看、签到或完成他人任务。
- 未到定位范围内签到、定位关闭、定位漂移。
- 未签到直接补货。
- 实补少于计划、多于计划或批次不一致。
- 货道容量不足、货道 SKU 绑定错误。
- 柜门打不开、设备离线、现场发现破损或库存差异。
- 补货完成按钮重复点击。
- 补货过程中退出小程序、断网、换手机和恢复。
- 一部分货道完成、一部分失败。

### 验收

- 商户、仓库、在途、柜机四类库存变化可追踪。
- 重复完成任务不得重复加库存。
- 任务异常可转运营待办，不得永久占用任务。

## 5.5 批次、保质期、下架、盘点和报损

### 正常逻辑

- 使用 FEFO 优先销售最早到期批次。
- 临期批次标记并生成下架或促销待办。
- 过期批次冻结销售并生成下架任务。
- 盘点记录账面数、实盘数和差异。
- 报损记录原因、数量、批次、操作人和时间。

### 边界与异常

- 无到期日期、生产日期晚于到期日期。
- 已过期商品入库或补入柜机。
- 已耗尽、冻结或已下架批次继续销售。
- 多批次混合扣减和退款恢复。
- 盘点数为负数、超容量或重复提交。
- 同一批次同时发生销售、盘点和报损。
- 报损数量超过现有库存。
- 已完成报损重复执行或撤销。

## 5.6 消费者账号、灰度资格和余额能力检查

### 正常逻辑

1. 消费者登录并进入灰度白名单。
2. 运营人工发放测试余额并填写原因。
3. 消费者查看余额和资金流水。
4. 开门前校验用户、风险、设备和最低余额。

### 边界与异常

- 未登录、Token 过期、账号禁用。
- 非白名单、未实名、风险冻结。
- 余额为 0、低于门槛、刚好等于门槛、高于门槛。
- 人工充值为 0、负数、超大金额。
- 重复充值请求和并发调账。
- 运营未填写原因或无权限操作。
- 用户尝试查看他人余额和流水。

### 验收

- 余额不能为负。
- 每次调整产生不可变流水和审计记录。
- 模拟余额界面必须明确标记为测试余额。

## 5.7 扫码、创建会话和开门

### 正常逻辑

1. 消费者扫码或输入柜机编号。
2. 小程序请求创建带幂等键的会话。
3. 交易服务验证用户、设备、余额和占用状态。
4. 设备服务下发开门命令。
5. 柜机 ACK 后会话进入购物中。

### 边界与异常

- 非法二维码、过期二维码、错误柜机编号。
- 相同幂等键并发请求 10 次。
- 不同幂等键并发抢占同一柜机。
- 连续点击、双击、页面回退后再次点击。
- 设备离线、维护、禁用、已占用。
- 开门命令发送失败、ACK 超时、迟到 ACK、重复 ACK。
- 用户取消与设备 ACK 同时发生。
- 会话创建成功但命令发送失败。
- 命令成功但前端响应丢失。
- 服务重启、Redis 数据丢失和本地缓存清除。

### 验收

- 一个幂等业务只创建一个会话和一个有效开门命令。
- 设备只能被一个有效会话占用。
- 用户重新进入小程序能恢复服务端活跃会话。

## 5.8 购物、关门、数据上传和识别

### 正常逻辑

1. 柜门打开，消费者自由取放商品。
2. 柜机记录门状态、视频、重力或其他传感器数据。
3. 关门后上传购物证据。
4. 视觉服务和传感器融合输出 SKU 与数量。
5. 交易服务生成唯一订单并结算。

### 商品组合用例

- 空开空关。
- 单商品一件。
- 单商品多件。
- 多 SKU 各一件。
- 多 SKU 多件。
- 取出后全部放回。
- 取出后部分放回。
- 快速取放、遮挡、叠放、替换位置。
- 柜内原有库存与实际不一致。

### 边界与异常

- 长时间未关门、重复开关门、门状态乱序。
- 购物期间设备掉线、重启或断电。
- 视频上传失败、部分上传、重复上传。
- 传感器数据缺失、异常跳变或与视频冲突。
- 识别任务超时、模型不可用、置信度不足。
- 视觉识别商品但库存不存在。
- 视觉类别未映射 SKU。
- 同一关门事件重复触发结算。
- 本地离线缓存补传产生重复事件。

### 验收

- 会话最终只能进入完成、争议、取消或明确失败状态。
- 无法可靠识别时进入人工争议，不得猜测扣款。
- 模拟器通过不代表真实视觉通过。

## 5.9 订单、余额扣款和库存扣减

### 正常逻辑

1. 根据识别结果计算商品明细、优惠和实付金额。
2. 在一个业务事务中创建订单、扣减余额、扣减批次库存并写流水。
3. 账单展示扣款前后余额和商品明细。

### 边界与异常

- 订单金额为 0、最小金额、大金额。
- 余额刚好等于订单金额。
- 最终金额超过开门时余额。
- 同一用户两个会话并发扣款。
- 重复关门、重复识别、重复结算回调。
- 扣款成功后服务崩溃。
- 扣款成功但库存失败；库存成功但扣款失败。
- 批次库存不足、商品价格在购物中途变化。
- 金额精度、四舍五入和小数位边界。
- 订单、账本或库存流水写入失败。

### 验收

- 一个会话只能有一个订单、一次有效扣款和一组库存变化。
- 余额不足转争议，不产生负余额。
- 事务失败不得产生资金或库存单边结果。
- 订单、余额流水、库存流水可双向查询。

## 5.10 账单、申诉、退款和客服

### 正常逻辑

1. 消费者查看账单和余额变化。
2. 消费者针对错识别、数量错误或其他问题提交申诉。
3. 运营领取工单并查看证据。
4. 运营选择维持原账单、部分退款、全额退款或人工确认商品。
5. 结果通知消费者并写入审计。

### 边界与异常

- 对不存在、他人或不可申诉订单提交申诉。
- 重复提交相同申诉。
- 多名运营人员同时领取或解决。
- 维持原账单不得产生资金流水。
- 部分退款和全额退款金额边界。
- 退款金额超过原扣款。
- 同一退款重复回调或重复点击。
- 退款与调账、结算、对账并发。
- 申诉处理后再次处理或重新打开。
- 处理超时、SLA 升级和客服转派。

## 5.11 设备故障和运营异常中心

### 异常类型

- 开门超时、长时间未关门、设备离线。
- 视频上传失败、识别失败、映射缺失。
- 余额不足、结算滞留、重复事件。
- 库存差异、补货异常、在途异常。
- 资金差异、退款失败、对账失败。

### 测试逻辑

- 自动扫描产生异常。
- 相同业务异常不能重复创建未解决记录。
- 领取、转派、备注、升级、解决和重新打开。
- 重试识别、人工确认商品、取消会话、释放设备。
- 异常解决失败、重复解决和并发处理。
- 高优先级异常告警与 SLA 超时。
- 所有处理动作保留操作人和处理前后状态。

## 5.12 商户经营、分账和财务对账

### 正常逻辑

- 商户查看所属设备、订单、库存、销售趋势、热销和滞销。
- 根据订单和协议生成商户分账。
- 财务执行日终订单、余额、库存、退款和分账对账。
- 差异进入异常中心并支持重跑。

### 边界与异常

- 商户跨范围查询其他商户数据。
- 日期边界、跨月、跨年和时区。
- 订单退款前后分账修正。
- 分账重复执行、部分失败和重试。
- 对账任务重复运行。
- 订单有扣款无流水、有流水无订单、库存不一致。
- 报表合计与明细不一致。
- 导出空数据、超大数据和敏感字段脱敏。

## 5.13 权限、隐私和审计

### 角色矩阵

- 消费者只能访问本人数据。
- 商户只能访问绑定商户和设备。
- 补货员只能操作分配任务。
- 仓库员只能操作仓储范围。
- 客服不能直接修改余额。
- 财务只能执行授权资金操作。
- 普通运营不能修改超级管理员权限。

### 攻击与边界

- 修改 URL、用户 ID、设备 ID、订单 ID 越权。
- 伪造、过期、注销后的 Token。
- 暴力登录、验证码滥用、重复提交。
- SQL 注入、XSS、文件上传类型和大小边界。
- 日志、导出和错误响应泄露手机号、密钥或支付信息。
- 审计记录被修改或删除。

## 6. 多端联调测试

## 6.1 消费者小程序—交易服务—设备服务—柜机端

验证扫码、会话创建、开门命令、ACK、购物状态、关门事件和会话恢复在各端一致。重点测试弱网、切后台、消息乱序、服务重启和迟到回调。

## 6.2 柜机端—视觉服务—交易服务

验证视频上传、重力数据、识别任务、SKU 映射、置信度、人工争议和重复结果。所有消息必须包含业务关联 ID 和幂等标识。

## 6.3 商户小程序—运营后台—仓库—补货员

验证要货申请、运营接单、仓库出库、在途、补货签到、实补、库存快照和商户库存刷新。任一端刷新或重进后状态必须一致。

## 6.4 消费者—客服/运营—资金账本

验证申诉、处理、退款、通知、余额刷新和资金明细。运营处理成功后，消费者端不得继续显示旧状态。

## 6.5 多实例和基础设施

- 多个 trade-service 实例处理相同回调。
- Redis 短时不可用、MQTT 重连、数据库主从延迟。
- 对象存储上传成功但回调丢失。
- 定时扫描任务被多个实例同时执行。
- Docker 容器重启后未完成业务自动恢复。

## 7. UI/UX 商业化设计与测试

## 7.1 设计系统

- 统一品牌色、状态色、字体、字号、间距、圆角和阴影。
- 统一按钮、表单、卡片、弹窗、标签、列表、骨架屏和空状态。
- 状态文案和颜色在三个前端保持一致。
- 图标统一，移除临时 Emoji 和不一致素材。
- 金额、库存、风险和危险操作具有明确视觉层级。

## 7.2 消费者小程序

- 首页突出扫码开门和当前余额。
- 开门前明确余额门槛、设备和风险信息。
- 购物中说明消费者直接取货，不要求页面选商品。
- 识别中显示进度、预计等待和异常处理方式。
- 账单突出商品、金额、扣款前后余额和申诉入口。
- 余额不足、离线、开门失败和识别失败使用专用状态页面。

## 7.3 商户/补货小程序

- 工作台优先展示待办、低库存、临期和设备异常。
- 补货流程适合现场单手操作，减少输入和页面跳转。
- 任务展示计划数量、实补数量、批次、效期和差异。
- 经营分析突出可行动信息，不堆砌无业务意义图表。

## 7.4 运营后台

- 以异常、资金风险和设备占用为首要信息。
- 补齐供应商、采购单、采购收货、出库、在途、批次、盘点和报损操作页面。
- 列表支持搜索、筛选、分页、固定关键列和明确状态。
- 危险操作显示目标对象、影响金额或数量，并要求二次确认。

## 7.5 页面状态和按钮

每个页面必须实际验证：

- 加载中、正常数据、空数据、搜索无结果。
- 接口失败、超时、断网、无权限和数据已失效。
- 所有按钮、Tab、筛选、搜索、分页、弹窗、返回和刷新。
- `loading`、`disabled`、防重复点击、成功/失败反馈。
- 中文、超长文本、Emoji、金额、时间和状态回显。
- iPhone、常见 Android、刘海屏、底部安全区、键盘遮挡。
- 运营后台 1366×768、1440×900 和 1920×1080。

逐按钮测试报告必须区分“实际逐项点击”和“同组件代表性抽样”，不能把抽样写成全覆盖。

## 8. 竞品对标计划

对 e 宝、大黄鹅及其他公开可访问的智能柜产品，以同一任务脚本测试并保存截图、步骤和耗时。

| 对标领域 | 指标 |
|---|---|
| 消费购物 | 扫码至开门步骤数、开门耗时、状态理解、结算耗时 |
| 异常体验 | 离线、失败、识别中、余额不足时是否说明原因和下一步 |
| 账单售后 | 商品证据、金额解释、申诉入口、退款进度 |
| 商户经营 | 实时库存、缺货、热销、滞销、毛利和设备健康 |
| 补货作业 | 路线、签到、建议、批次、效期、异常上报、完成耗时 |
| 运营效率 | 异常优先级、领取转派、批量处理、SLA 和审计 |
| 供应链 | 采购、仓库、在途、盘点、损耗和效期闭环 |
| UI 设计 | 信息层级、留白、字体、颜色、触控、空状态和可信感 |

## 9. 非功能测试

## 9.1 性能与容量

- 10、50、100 名用户并发创建会话。
- 同一柜机高并发抢占。
- 批量关门、结算和退款回调。
- 视频并发上传和识别队列堆积。
- 大量库存、订单、流水和异常列表查询。
- 日终对账、异常扫描和商户报表同时运行。

记录 P50、P95、P99、错误率、数据库连接、CPU、内存、MQTT 延迟和队列积压。

## 9.2 稳定性与容灾

- 关键服务滚动重启。
- 数据库、Redis、MQTT、对象存储短时不可用。
- 网络分区、磁盘空间不足、时间偏移。
- 数据库备份恢复和对象存储恢复。
- 制定并验证 RTO、RPO。
- 单点灰度连续运行至少 14 天，无未闭环 P0 事故。

## 9.3 可观测性

- 请求 Trace 能关联用户、会话、订单、设备、识别任务和资金流水。
- P0/P1 异常具有日志、指标、告警和运营工单。
- Prometheus/Actuator、日志采集和错误告警正常。
- 告警有去重、恢复通知、负责人和升级规则。

## 10. 真实硬件与视觉专项

模拟环境通过后仍必须完成：

- 真实门锁开关、门磁、心跳、摄像头、重力传感器测试。
- 断电、断网、弱信号、设备重启和离线补传。
- 顶摄、侧摄、重力和库存快照融合。
- 商品专用训练模型，不使用通用 COCO 模型直接做真实 SKU 扣款。
- 至少 1,000 次真实取放组合测试，分别统计 SKU、数量和组合订单准确率。
- 低置信度、遮挡、相似包装、反光、光线变化和商品换包装。
- 模型版本、灰度发布、回滚和准确率漂移监控。

在专用模型和真机测试通过前，不允许将识别结果用于真实资金扣款。

## 12. 执行阶段

### 阶段 A：基础安全门禁

- Maven 全量测试和 Testcontainers。
- 三个前端生产构建。
- 会话幂等、余额、订单、库存事务和权限测试。
- 修复所有 P0 缺陷。

### 阶段 B：商业 UI 与缺失页面

- 建立设计系统。
- 重构消费者购物链路和账单。
- 重构商户补货链路。
- 补齐采购、仓储、在途、批次、盘点和报损后台页面。

### 阶段 C：完整供应链联调

- 从供应商和采购单开始，走到采购收货、仓库、出库、在途、补货和库存快照。
- 验证批次、效期、报损和盘点。

### 阶段 D：完整消费者与运营联调

- 登录、充值、开门、购物、结算、账单、申诉、退款和异常解决。
- 执行所有失败、超时、重复和并发场景。

### 阶段 E：竞品和多端 UI 验收

- 竞品同任务对标。
- 三端逐页逐按钮。
- 常见设备尺寸、弱网和中文显示。

### 阶段 F：预发布和灰度

- 性能、故障注入、备份恢复和可观测性。
- 真机和专用视觉模型。
- 1–3 台柜机、受控消费者连续灰度。

## 13. 缺陷等级与发布规则

| 等级 | 示例 | 发布规则 |
|---|---|---|
| P0 | 重复扣款、负余额、错扣无法恢复、设备无法释放、越权资金操作 | 必须修复，禁止灰度 |
| P1 | 订单/库存不一致、补货重复入库、关键流程无法完成、严重 UI 遮挡 | 必须修复或关闭功能 |
| P2 | 次要流程错误、明显体验问题、报表误差 | 正式上线前修复 |
| P3 | 文案、轻微样式和低频易用性 | 进入明确版本计划 |

## 14. 最终上线准入标准

- Maven 全量测试通过，Testcontainers 不得跳过。
- 消费者、商户小程序和运营后台生产构建通过。
- P0、P1 用例全部通过，P0/P1 缺陷为 0。
- 相同幂等请求不会重复创建会话、订单、扣款、退款或库存变化。
- 余额、订单、库存、退款、分账日终差异为 0，或全部进入可追踪异常。
- 开门成功率不低于 99.9%，关门事件完整率不低于 99.99%。
- 真实商品组合识别准确率达到业务设定阈值，低置信度全部进入人工处理。
- 三端无乱码、遮挡、死按钮、无限加载和无反馈危险操作。
- 商户和角色数据隔离通过越权测试。
- 核心告警、审计、备份和恢复演练通过。
- 单点灰度至少连续运行 14 天，无未闭环 P0 事故。
