# AI 开门柜浏览器全流程测试报告

测试日期：2026-07-11

## 覆盖角色

- 消费者小程序（通过同源 H5 测试壳运行同一套 uni-app 页面代码）
- 商户/补货小程序（通过同源 H5 测试壳运行同一套 uni-app 页面代码）
- 平台运营后台

H5 仅用于 browser-use 自动点击测试，不作为正式商户或消费者 Web 产品部署。

## 已通过的完整流程

1. 消费者手机号登录。
2. 运营为灰度消费者发放测试余额，余额从 ¥94.00 调整至 ¥95.00。
3. 模拟购物车设置为可口可乐 1 件、纯牛奶 1 件。
4. 消费者输入 CAB-001 并点击开门。
5. 页面进入“门已开 · 购物中”，模拟器等待 20 秒后关门。
6. 系统生成 ¥8.00 订单，余额从 ¥95.00 扣减至 ¥87.00。
7. 账单展示两项商品、扣款前后余额和支付状态。
8. 消费者提交账单申诉。
9. 运营进入争议审核，查看工单并选择“维持原账单”。
10. 二次确认后工单结案，余额保持不变。
11. 消费者模拟充值 ¥20.00，余额从 ¥87.00 变为 ¥107.00，流水可见。
12. 消费者提交设备故障报修。
13. 报修生成 HIGH / DEVICE_FAULT 运营异常。
14. 运营查看详情、领取并填写处理结果，异常转为 RESOLVED。

## 测试中修复的问题

- 运营/商户密码登录字段由 `phone` 修正为 `phoneNumber`。
- 争议审核增加详情、维持原账单和免单退款操作。
- 后端增加安全的 `KEEP` 决策，维持原账单时不产生资金变化。
- 消费者和商户“我的”页面增加底部安全区，避免 TabBar 截获点击。
- 商户概览设备字段改为 `deviceOnline` / `deviceTotal`。
- 消费者故障报修接入统一运营异常中心。
- 增加多商品模拟结算脚本 `scripts/set-simulator-cart.ps1`。
- H5 测试代理增加 API 代理与消费者端 Origin 重写。

## 已知限制

- 当前视觉服务为 mock；YOLO 运行依赖未安装，不能用于真实资金扣款。
- 当前 Docker Testcontainers 识别问题仍需在 CI 或标准 Maven 环境复验。
- 异常中心历史数据包含较多已自动解决的设备离线记录，需增加默认状态筛选或归档。
- 商户货道编辑与定价取决于商户权限配置，本次账号为只读权限。
- browser-use 通过 PowerShell 管道输入中文时会发生编码损失；自动化测试数据已改用英文。真实页面直接输入中文正常。
