# 一、设备照（实体图）

## 要不要拍无人柜？

**要，必须是无人柜（智能售卖柜）的真机实拍。**

官方要的是「设备照（如有）」+「设备/产品介绍及实体图」——
评审要确认**你申请的场景用的就是这个设备**，所以必须是商用真机。

## 拍几张、怎么拍

| # | 照片 | 关键要求 |
|---|---|---|
| 1 | **柜机正身** | 全身入镜，能看出这是台智能售卖柜（屏幕 + 货舱 + 扫码区） |
| 2 | **柜机侧身 45°** | 能看出柜体厚度与货舱结构（证明是实体柜不是贴图） |
| 3 | **柜机二维码特写** | **二维码占画面 1/3 以上，且能扫出来**——扫出来应进「AI开门柜-消费者」小程序，不是空白页 |
| 4 | **货舱内部** | 拍到**真实陈列的商品**（饮料/饭团等），别拍空柜 |
| 5 | **摆放场景全景** | 柜机放在办公区/餐厅/园区里的样子，带环境参照 |

## 四个坑

1. **❌ 别用效果图 / 3D 渲染图** —— 官方要"实体图"，评审人工核，渲染图一眼看出
2. **❌ 二维码要能扫出来** —— 消费者开门的那个码，不是样例码
3. **❌ 别只拍一台** —— 有多个型号或不同场景（办公柜 / 餐饮柜）就各拍一台
4. **❌ 别把柜机 PII 打码** —— 屏幕上的订单号、用户昵称如果有，顺手遮一下（不影响评审）

# 二、业务/产品点位信息

## 官方要什么

「城市、地址、数量、场景图等」——**两样东西**：
1. **一张表**（点位清单）
2. **一批照片**（场景图，与表格一一对应）

## 表格：13 个字段

| 字段 | 填什么 | 样例 |
|---|---|---|
| 序号 | 顺序号 | 1 |
| **城市** | 到市级即可 | 深圳市 |
| 点位名称 | 对方给你的点位称呼 | 某科技公司 A 座 18 层 |
| **详细地址** | 写到门牌/楼层 | 深圳市南山区科技园科苑路 15 号 XX 大厦 18 层 |
| **柜机数量** | 该点位几台柜 | 2 |
| 设备编号 | 柜机 ID，多台用 `/` 分隔 | EG943322621391 / EG500909625160 |
| 柜型 | 设备型号/类型 | 智能售卖柜 |
| 场景说明 | 投放位置 + 消费场景 | 办公区电梯厅旁，24 小时可取 |
| **场景图文件名** | 与图片文件名严格一致 | 01_101.jpg; 01_102.jpg |
| 点位负责人 | 联系人 | 王经理 |
| 联系电话 | 联系人电话 | 13800000001 |
| 合同起止 | 投放合同期限（可选，但建议填） | 2025-01-01~2027-12-31 |
| 经纬度 | 选填 | 22.5412,113.9510 |

## 🔴 三个必守的规则

1. **一个物理点位一行** —— 同一地址有多台柜机，**合并成一行**、柜机数量填实际台数。
   别一台柜一行（评审会以为是不同点位）。
2. **场景图文件名与表格严格一一对应** —— 表格写 `01_101.jpg`，图片文件就叫 `01_101.jpg`，
   放在同一目录。评审对照着看，对不上等于没交。
3. **柜机数量合计 = 设备照里的柜机总数** —— 两份附件数字要一致，这是评审最容易交叉核对的地方。

## 场景图拍法

每个点位**至少 1 张**，画面要含：
- 柜机全貌
- 摆放环境（周围是什么）
- **周边参照物**（门牌号、工位号、招牌、楼层指示牌）—— 证明这柜机真在这个位置

> 💡 如果点位很多（几十个），可以：
> - 表格列全（这是必须的）
> - 场景图每个点位 1 张，**选代表性点位多拍几张细节图**（满货柜、扫码特写、排队场景）

## 两种做法

### 🔴 做法 A（本次拍板采用）：从**易购老系统**导出

邮件里的经营数据（1,109 台柜机、日均 13,686 笔）来自**易购老系统**在收款的交易，
点位必须取**易购的柜机与点位** ⇒ 数据源在老系统库（阿里云 RDS MySQL），不在新系统库。

**三步：**

```bash
# ① 在阿里云 DMS 跑 docs/sql/easygo_payscore_sites_export.sql → 导出 CSV
#    （一次导出全部在册柜机，不用一台台跑）
# ② 转换成官方 13 字段表格
python scripts/easygo_sites_to_payscore_table.py <导出的.csv>
# ③ 场景图：从导出表的「点位照片PC/移动端」两列批量下载（老系统已有！），
#    按点位表的「场景图文件名」重命名，与表格一一对应
```

产出：`payscore-sites.csv`（13 字段表格）/ `payscore-sites.md`（评审清单）/ `payscore-sites-pending.csv`（地址待补）

📎 完整操作指引见 **`docs/EASYGO_SITES_EXPORT_GUIDE_2026-10-27.md`**（含字段来源速查表）。

### 做法 B：新系统库导出（仅当新系统已有投放点位时用）

```bash
python scripts/export_payscore_sites.py
```

⚠️ 该脚本查的是**新系统**的 `device_info.install_address` / `site_contract`，
**在易购老系统的 1,109 台上无数据**。本次不适用。

### 做法 C：手工填模板

```bash
python scripts/make_payscore_sites_template.py
```

产出 `docs/figures/payscore-sites-template.csv`（含 2 行示例 + 逐条填写说明），照着填。
