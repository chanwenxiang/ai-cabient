# ai-cabinet 三端 UI 审计报告

> 审计时间：2026-09-12  
> 审计范围：consumer-mp（消费者小程序）、merchant-mp（商家小程序）、admin-vue（运营后台）  
> 依据：用户提供的 3 张截图 + 三端源码抽样审查

## 一、全局 / 跨端问题（设计系统层）

| 编号 | 严重程度 | 问题 | 影响范围 | 位置/证据 | 修复建议 |
|------|----------|------|----------|-----------|----------|
| G01 | P1 | 三端品牌主色不统一 | 全端 | consumer `--brand:#047857` / `--brand-deep:#064e3b`；merchant `--brand:#0f766e` / `--brand-deep:#134e4a`；admin `--app-primary:#0f766e` | 统一品牌色板，consumer 与 merchant/admin 二选一或按端只区分深/浅，禁止同一产品出现两套绿色 |
| G02 | P1 | CSS 变量命名三套体系 | 全端 | admin 用 `--layout-*`，小程序用 `--text-*` / `--page-bg` | 建立统一 Design Token：`--color-primary`, `--color-text-primary`, `--color-bg-page`, `--spacing-md` 等 |
| G03 | P0 | 硬编码颜色值遍布页面 | 全端 | 几乎所有 `.vue` 文件均含 `#xxxxxx`；consumer `help.vue` 出现 `#191919` `#6b7280` `#059669` 等 | 全部收敛到 token；lint 禁止源码出现未在 token 中声明的色值 |
| G04 | P1 | 字号 / 字重 / 行高无统一 scale | 全端 | 20rpx~44rpx 任意出现；`font-weight: 600/650/700/800` 混用 | 定义 typography scale：标题 H1/H2/H3、正文、辅助、标签等固定几档 |
| G05 | P1 | 圆角 / 阴影 / 间距不统一 | 全端 | card 圆角有 20rpx/22rpx/24rpx/16rpx；阴影色值/透明度各不相同；卡片 margin 消费者 `0 0 16rpx`、商家 `20rpx` | token 化 `--radius-card`, `--radius-control`, `--shadow-card`, `--page-gutter` |
| G06 | P1 | 重复组件实现且样式不一 | consumer / merchant | `app-nav-bar.vue`、`empty-state.vue` 各端分别维护；返回图标一个用 `‹`、一个用 `‹` 但布局算法不同 | 抽到 `packages/shared-uni/components` 统一维护，或至少对齐视觉与行为 |
| G07 | P1 | 按钮类名/实现混乱 | 小程序端 | `.btn-primary` `.action-btn` `.primary-btn` `.empty-btn` `.retry` `.tip-btn` 多种并存 | 封装统一 `<AppButton>` 组件，支持 variant：`primary / ghost / outline / danger / text` |
| G08 | P2 | 缺少统一图标系统 | 全端 | 列表项无图标；返回用文本 `‹`；状态/操作靠颜色和文字区分 | 引入统一图标库（如 iconfont / svg sprite），为关键操作配图标 |
| G09 | P1 | 空态 / 错误态 / 加载态实现不一致 | 全端 | `empty-state` 组件样式各端不同；admin 部分页面仍直接写 `加载中…` | 制定统一状态组件规范，含图标、标题、描述、操作按钮 |
| G10 | P1 | 可访问性（a11y）薄弱 | 全端 | 大量可点击 `<text>` 未加 `role="button"`；图标无 `aria-label`；状态仅依赖颜色 | 统一加 role/aria-label；错误态增加文案说明；确保颜色对比度 ≥ 4.5:1 |

## 二、消费者小程序（consumer-mp）

### 2.1 帮助中心页（`pages/help/help.vue`）

| 编号 | 严重程度 | 问题 | 位置/证据 | 修复建议 |
|------|----------|------|-----------|----------|
| C01 | P1 | 顶部导航栏标题与页面大标题重复 | `app-nav-bar title="帮助中心"` + `.hero-title` 同为「帮助中心」 | 去掉 `.hero-title`，或在导航栏使用更轻量的返回标题；避免同一词汇三行重复 |
| C02 | P1 | 右侧操作文字颜色/字重不统一 | `.support-action` 为 `#059669`，但与全局链接色 `--brand` `#047857` 不一致；无 hover/pressed 反馈 | 收敛到 `--color-link`，统一操作文字样式；增加 active 态 |
| C03 | P1 | 操作项缺少图标，可识别性差 | 列表只有文字「拨打 / 复制 / 去查看」 | 每项左侧增加语义图标（电话、复制、公告、反馈、报修、消息、地图） |
| C04 | P2 | FAQ 展开符号 `+/-` 与品牌风格不搭 | `.faq-toggle` 使用 `+` / `−` 字符 | 使用统一图标（chevron-down / chevron-up），并规范动画 |
| C05 | P1 | 卡片样式与全局 card token 不一致 | help 页 `.card` 圆角 `20rpx`、margin `0 24rpx 20rpx`；App.vue `.card` 圆角 `24rpx`、margin `0 0 16rpx` | 统一使用全局 `.card` 或扩展 modifier，不重复定义基础样式 |
| C06 | P1 | 硬编码大量文字颜色 | `#191919` `#111827` `#1f2937` `#4b5563` `#6b7280` 等 | 替换为 `--color-text-primary` / `--color-text-secondary` / `--color-text-muted` |
| C07 | P2 | 「账单有疑问？」提示卡片风格孤立 | `.tip-card` 使用橙色系渐变 `#fff7ed` / `#fed7aa` / `#9a3412` | 如果全局只有一种提示色，应收敛；若需突出，用统一 warning/info 提示组件 |

### 2.2 首页 / 扫码购物页（`pages/index/index.vue`）

| 编号 | 严重程度 | 问题 | 位置/证据 | 修复建议 |
|------|----------|------|-----------|----------|
| C08 | P0 | 授权弹窗两个按钮宽度不一致 | `.landing-sheet-actions` 中「取消」和「去登录」并排，视觉上一个窄一个宽 | 弹窗底部操作按钮统一宽度（推荐等宽或主按钮略宽），使用 `gap` 保持一致 |
| C09 | P1 | 弹窗遮罩过深，背景完全不可辨 | `.landing-mask` 颜色未在代码片段中显式看到，但截图显示背景几乎全黑 | 降低遮罩不透明度（建议 `rgba(0,0,0,0.45~0.55)`），保留背景上下文 |
| C10 | P1 | 「继续在本柜购物」卡片使用玻璃态/半透明，与整体扁平绿风格冲突 | `.resume-card` `background:rgba(255,255,255,0.14)` + 半透明边框 | 改为实心品牌色卡片或统一 sheet 样式；玻璃态慎用，避免在不同机型上糊成一团 |
| C11 | P1 | 扫码按钮与弹窗层级关系混乱 | 弹窗出现时扫码大圆按钮仍可见/可点 | 弹窗出现时禁用/隐藏底层主操作，或确保弹窗 z-index 足够且遮罩拦截点击 |
| C12 | P2 | 「附近找柜」下划线链接样式过时 | `.nearby-link` `text-decoration: underline` | 改为文字按钮样式（带右箭头图标），与小程序现代设计一致 |
| C13 | P1 | 状态颜色硬编码 | `.device-status.offline` `#fa5151`；`.device-change/report` `#576b95` | 收敛到 `--color-danger`、`--color-link` |
| C14 | P1 | 购物页卡片/提示框圆角/间距不统一 | `device-bar` 圆角 22rpx；`shopping-banner` 圆角 16rpx；`catalog-notice` 圆角 15rpx | 统一到 `--radius-card` / `--radius-control` |
| C15 | P1 | 顶部品牌区文字层级过密 | `.brand` 44rpx 800 字重 + `.tagline` + `.pay-badge` 挤在状态栏下 | 增加呼吸空间；检查小屏手机是否顶穿胶囊 |
| C16 | P1 | 空态组件 empty-state 图标为方角 | `empty-icon` `border-radius:24rpx` 与卡片 24rpx 一致，但与圆形/椭圆设计语言不搭 | 统一空态图标为圆形或品牌形状； Merchant 端也同步 |

## 四、运营后台（admin-vue）

### 4.1 设备详情页（`views/devices/DeviceDetailView.vue`）

| 编号 | 严重程度 | 问题 | 位置/证据 | 修复建议 |
|------|----------|------|-----------|----------|
| A01 | P1 | 「柜机二维码」卡片内容区大片空白 | `qr-body` 在二维码未加载时只显示 tiny 文字 | 增加骨架屏 / 占位图 / 空态插图，避免卡片空洞 |
| A02 | P2 | 统计 tile 使用 `<button>` 但无交互反馈 | `stat-tile` 用 button 标签承载纯展示数据 | 改为 `div` 或设计为可点击的 KPI 卡片；若可点则加 hover/active 态 |
| A03 | P1 | IMEI 未绑定状态展示不直观 | `el-input disabled value="未绑定"` | 使用空态标签（如 `--` 或「未绑定」Tag），而不是禁用输入框 |
| A04 | P1 | 标签页与面包屑视觉层级弱 | 截图中「设备详情 / 补货调度」Tabs 与 breadcrumb 间距、颜色接近 | 增加面包屑与 Tabs 之间的间距；Tabs 使用更明显的 active 态 |

| A07 | P1 | 表格所有列强制居中，ID/时间等左对齐更易读 | `main.css` `.layout-main-scroll .el-table th/td { text-align: center !important }` | 取消全局强制居中；仅操作列居中，文本列默认左对齐，金额列右对齐 |

| A09 | P2 | 弹窗/抽屉宽度规则复杂，仍有潜在裁切风险 | `main.css` 中大量 `.el-dialog` `.el-drawer` 覆盖 | 抽成 mixin 或工具类；所有业务弹窗使用 `dialog-wide` / 默认两类 |

## 五、可访问性 & 交互统一问题

| 编号 | 严重程度 | 问题 | 影响范围 | 修复建议 |
|------|----------|------|----------|----------|
| X01 | P1 | 可点击文本未声明 role | consumer `index.vue` `.error-action` `.nearby-link` `.manual-link` 等 | 统一加 `role="button"` 或使用 `<button>` |

| X05 | P1 | 小程序端 H5 桌面预览框硬编码 390px | `App.vue` `@media (min-width:600px)` | 支持响应式断点，或允许在更大屏幕上铺满而非固定手机框 |
