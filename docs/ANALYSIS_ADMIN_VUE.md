# 运营管理后台 (admin-vue) 分析报告

> 对照市面 AI 开门柜运营后台（中吉云、智桥、魁鲸类 SaaS）重写。
> **勿再将「有菜单/有页面」等同于「可日运营」**。

## 一、项目概况

| 项目 | 信息 |
|------|------|
| 路径 | `clients/admin-vue` |
| 技术栈 | Vue 3.4 + TypeScript 5.4 + Element Plus 2.7 + Vite 5.2 |
| 路由数 | ~35（含 redirect） |
| 构建产物 | `services/trade-service/.../static/admin/` |
| 总体成熟度 | **演示台 → 日运营中台过渡中**（非 90% 完成） |

## 二、竞品能力对标

| 能力域 | 市场标配 | 本项目现状 | 成熟度 |
|--------|----------|------------|--------|
| 工作台 | KPI、缺货、告警 SLA、一键处理 | KPI + 异常优先队列 | 部分完成 |
| 设备运维 | 在离线、远程开门/锁机/重启、温控、故障 | 列表在离线；详情含货道+运维面板（远程指令） | 进行中 |
| 货道/库存 | 陈列、缺货预警、上下架 | 货道编辑有；缺货→补货联动 | 部分完成 |
| 会话/订单 | 时间线、录像、退款、改单 | 退款/争议/异常较完整；时间线已补 | 部分完成 |
| 视觉 | 低置信度复核、SKU 建模 | SKU+Demo；生产应隐藏 Demo | 部分完成 |
| 补货 | 缺货驱动、派员、路线、盘点 | 路线/要货/缺货建议 | 部分完成 |
| 商户/加盟 | 多级组织、抽成、结算 | 商户分账可用；加盟页已移除（后端半成品未挂 UI） | 部分完成 |
| 财务 | 对账、分账、毛利 | 页面有；真实微信分账依赖进件 | 演示级 |
| 营销/会员 | 券、活动、C 端用户 | 券/活动有；灰度为调余额，非 CRM | 演示级 |
| 系统 RBAC | 账号/角色/菜单/审计 | 较齐（若依风格） | 可用 |

## 三、模块成熟度清单

### 相对扎实

- 登录鉴权、权限裁剪侧栏、全局搜索
- 工作台异常队列跳转
- 订单退款、争议审核、异常中心（领取/转派/人工结算/免单）
- 商品与识别配置、录像上传
- 系统：账号/角色/菜单/字典/参数/审计/操作日志

### 半成品

- 设备列表曾无 bulk selection；详情曾仅货道
- 补货偏配置，缺货驱动在补强
- 分账依赖真实支付配置
- 分析/报表需区分 MOCK 与生产数据源
- 风控事件列表动作弱

### 已处理缺陷

| 问题 | 处理 |
|------|------|
| `franchise/index.vue` 乱码空实现 | 删除死页；加盟能力明确不做 UI（见商户分账） |
| 多页无效 `selection` 列 | 移除无批量逻辑的勾选列 |
| 识别 Demo / 灰度调余额进生产 | `VITE_ENABLE_TEST_TOOLS` / 非 PROD 才暴露 |

## 四、上线边界（管理端）

**本阶段管理端可做到**：内部余额/mock 支付下，设备可管、异常可结、资金可审计、测试能力可隔离。

**不在管理端单独解决**：微信小程序发布与执照、真实微信支付进件、真实门锁/摄像头硬件、生产级 YOLO 模型。

## 五、整改分期

### P0（可日运营最小集）

1. 设备详情升级为运维页（状态/货道/关联单据/远程指令）
2. 清理无效 UI、franchise 死页、生产开关
3. 重写本文档

### P1（竞品日运营闭环）

1. 缺货预警 → 一键生成补货
2. 异常 SLA 字段与展示
3. 会话/订单时间线 + 录像入口
4. 设备列表服务端分页与筛选

### P2（不阻塞试运营）

真实会员 CRM、营销效果看板、柜机广告位、可视化大屏。
