# 上线前全量 UAT 数据测试计划（v2，2026-11-04 定稿，D0 已执行）

> 方式：**uat 空库切栈 + 三端真实操作**（admin=浏览器手点、小程序=微信开发者工具手点；API/SQL 只用于造数与库断言，不代替操作）。
> 铁律：每条流程必须真实点写操作；问题当场领 MA 号（接 MA-162 后新号段）；P0 发现即停轮。
> 本计划由用户拍板三项补充机制（见 §1），执行者为当前唯一活跃会话（其它会话已结束）。

## 1 · 用户拍板的三项机制（本轮测试的方法论核心）

### 1.1 每轮前后对账（轮首快照 → 轮末快照 → 差额必须被业务解释）
- 轮开始：记录资金/库存/台账三面快照（wallet_account 余额与台账 SUM、device_sku_inventory 台账与 device_sku_lot 批次、merchant 余额）
- 轮结束：再取快照，**逐笔差额必须能对上本轮业务动作**（如：余额 -486=订单实付、+200=充值；库存 -2=销售回库、+50=入库）
- 对不平 = 发现缺陷（这正是历史上 MA-147/MA-049 类问题的测试法）

### 1.2 全库表覆盖检查（181 张表，数据库级的测试覆盖率证明）
- 基线表清单：`docs/uat/baseline-tables.txt`（181 表）
- 每轮末对触达表打勾；**测试总结时全表三分类**：
  ① `已触达`（count>0 或产生过数据）② `刻意空`（设计上无数据：如 ali 冗余、按需启用的表——逐表写明原因）③ `未触达` = **测试缺口**（要么补测对应业务，要么定性为死表建议清理——这就是「有数据要吗」的正式答案机制）
- 覆盖清单随轮次更新于 `docs/uat/table-coverage.md`

### 1.3 流程扩量（在七轮基础上补充的业务面）
- 审批流（approval_definition/instance/task 三表全链：定义→发起→审批→会签）
- 设备生命周期（入库→绑定→租机押金/账单→退役）与租赁账单三态
- 发票申请→开具→驳回；站点合同→租金账单
- 将邑映射（挂接/学习库/审核/模型部署记录）、采集会话（如有设备）
- 媒体资产上传→引用→删除（引用计数拦截）
- 外部渠道导入（模板→预览→commit→月结联动——MA-101 回归）
- 反馈/报修双通道（消费者报修 vs 运维工单分表）
- 数据管理后台（AdminDataManage 白名单内改数+审计留痕核对）
- OTA 发布→灰度→下架（记录面，无真机不推设备）
- 操作日志/审计页每轮顺带核对（写动作必须有痕——MA-091 家族回归）

## 3 · R6 定时/日结/月结专项（逐任务）

| 任务 | 触发 | 断言表 | 幂等验证 |
|------|------|--------|----------|
| 日费用日扣 | `rerun-daily-fees?feeDate=` | merchant_fee_ledger + wallet 流水 | 重复 rerun 不双扣（唯一索引） |
| 日结收入通知 | scheduler taskKey run | notification(DAILY_INCOME) | 不重发 |
| 佣金日结 | 周期扫描型（无手动端点）：造昨日 GMV+佣金配置 → 等下一轮 | wallet_ledger COMMISSION = gmv×bps | 重扫不双发 |
| 机器账单月出账 | `machine-payee-bills/generate?billMonth=`（含 >10000bps 应 400——MA-090 回归） | machine_payee_bill 行 | 再 generate 409 |
| 场地租金/数据费账单 | generate 端点 | 账单行+appendLog | 再 generate 409 |
| 月结差异处置 | close-sheets→approve→disposition | inventory_write_off 索赔行 | 并发双击不双挂 |
| 资金对账 | `reconciliation/run?date=` | recon 行+MISMATCH | 重跑删旧重建不残留 |
| 欠款催缴 | 造 PENDING 欠款观察阶梯 | 通知/风控事件 | 不重复催同档 |
| 一致性巡检 | consistency run / fix | data_consistency_record | FIXED 重放拒绝 |
| 效期/补货建议 | expiry ensure / suggest | 告警+拉货任务 | 同批次不重开 |
| SMS 到达率巡检 | sms-delivery-report / scheduled 链 | 巡检记录 | 重复不重报 |
