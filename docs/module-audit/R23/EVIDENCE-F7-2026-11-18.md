
结论：**已应用行**与仓库迁移文件逐条一致，部署链的 drift 闸有 PASS 证据。

🔴 必须同时说清楚边界：生产库当前最新版本是 **453**，本地迁移已到 **496**；454–496 属

## 3. 备份（L-04）✅

**发现（严重）**：生产服务器 **没有任何备份 cron**，`/var/backups/aicabinet` 最新备份是 **2026-11-06 16:17**，即 12 天无新备份；且 `BACKUP_REMOTE_CMD` 未配置，所有副本只在本机 `/var/backups`（同盘）。

本次已做：

1. 立即手工补跑一次本地备份（只读 DB）。
2. 安装每日 02:10 cron，并从 `/etc/aicabinet-backup.env`（`600`）注入归档环境：

```
10 2 * * * cd /data/apps/ai-cabinet && set -a && . /etc/aicabinet-backup.env && set +a && /bin/bash scripts/backup-database.sh >> /var/log/aicabinet-backup.log 2>&1
```

3. **异地归档已打通**：复用将邑视频的 OSS bucket `ai-cabinet-by`（cn-shenzhen），
   RAM 仅授 `backups/aicabinet/*` 的 Put/Get/Delete（不含 `jiangyi-video/*`）。
   该子账号只有 `sts:AssumeRole`，直写任何前缀都会 403（实测 `AccessDenied`），
   因此脚本走 `AssumeRole` 换 15 分钟临时凭据，再用 `ossutil` 上传；
   endpoint 用同地域内网 `oss-cn-shenzhen-internal.aliyuncs.com`。

   实测（2026-11-18 17:58）：

```
local backup ok size=1214016B file=/var/backups/aicabinet/20261118-175811/aicabinet.dump
[backup-offsite-oss] offsite ok bucket=ai-cabinet-by key=backups/aicabinet/20261118-175811/aicabinet.dump size=1214016
```

   独立复核（另起 STS 会话 `ossutil stat`）：

```
Content-Length : 1214016
Last-Modified  : 2026-11-18 17:58:12 +0800 CST
```

   本地与远端字节数一致，异地副本成立。远端 key 保留本地时间戳目录，
   每天一份、不互相覆盖；本地保留 7 天由 `backup-database.sh` 处理。

**待办（非阻塞）**：给 `backups/aicabinet/` 配 OSS 生命周期（如 90 天转低频/删除），
避免长期无限增长；不影响本次「异地备份」成立。
