## 2. 逐屏规格

### ① 商品展示页 —— 标签

**位置**：商品卡（`index.vue` 商品列表项）底部或价格行旁。

**标签结构**（规范 P14 标准样式）：
```
[微信支付分 logo]  |  先取后付
```
- 分隔符 `|` 为官方排版的一部分，**不可删**
- 「先取后付」为业务动词替换位（规范 P14「先吃后付」「先住后付」示例）；本场景取「**先取后付**」
- 标签颜色/大小/风格**需与支付分 logo 协调且不影响 logo 识别性**
- 标签内文字颜色 `#07C160`（规范 P13，浅色背景下）

**可选极简样式**（P15 无 logo 版）：`微信支付分 | 先取后付` 纯文字，适用于纯文字标签位。

**⛔ 禁止**（P14/P15 错误示例）：
- 不得写成「微信支付 | 先取后付」（漏「分」字）
- 不得写成「微信支付分 先取后付付款」（多加字）
- 不得改变 `|` 与文字的间距比例
- 不得在标签内追加「550分」等文案到**无分数要求版**标语上

**分数要求版的选择**：官方 P5 明确「如果业务有明确的微信支付分分数要求，需选择带分数要求的标准版本」。
⇒ **我方 `PAYSCORE_MIN_SCORE` 默认 550，若页面要展示分数门槛，必须用带分数要求版**
`[微信支付分 logo] | 先取后付` + 下方 `550分及以上优享`；若不展示分数门槛，用**标准版本**。
⇒ 🔴 **待用户拍板**：是否在 C 端露出「550分及以上优享」？
- 露出＝转化更好（用户知道能不能用）但分数是微信侧评估、可能不准；
- 不露出＝页面干净但用户开通失败时无预期。
**建议：不在商品页露出分数，只在开通成功页/失败提示里说明「微信支付分评估未通过」**，
这样避免与微信侧实际门槛不一致被判定误导。

### ② 订单提交页 —— 按钮 + 基本说明

**必备元素**（申请模板 §5 + 规范 P11）：

| 元素 | 内容 | 落点 |
|---|---|---|
| 商品信息 | 逐件商品名称 + 数量 + 单价（与开门前价目**同源同价**，CB-063 结论 3） | `index.vue` 结算区 |
| 计费规则 | 「按实际取货商品金额计费」——**必须写明动态金额语义** | 结算区信息行 |
| 支付方式 | 展示「微信支付分」标签（复用①的标签素材）+ 若有其他可用渠道则并列 | `pay-channel.ts` 驱动的渠道选择 |
| 主按钮 | 品牌绿 `#07C160` 底 + 白字 | 结算抽屉底部 |

**文案口径**：
- 主按钮「**确认开通并开门**」——明确包含「授权」动作，符合支付分「用户主动授权」要求
- ⛔ **不得**出现「免确认」「授信」「代扣」「先付后享」「无需确认」等词（R8 精神 + 微信支付分协议口径）
- 不得承诺「一定成功开通」「保证免密」——开通与否由微信侧评估决定

**已有文案对齐检查**（本仓现状，需在实现时核对）：
| 位置 | 现状文案 | 是否合规 |
|---|---|---|
| `verify.vue` hero-sub | 「完成后即可扫码开门，关门自动扣款」 | ✅ 可用，但建议补「微信支付分评估」字样说明门槛 |
| `open-prep-drawer.vue` payDesc | 「推荐开通微信支付分：关门后自动扣款，无需每次确认。」 | ⚠️ **「无需每次确认」接近 R8 禁词**，建议改为「关门后自动扣款」 |
| `open-prep-drawer.vue` payDesc（支付宝分支） | 「推荐开通支付宝免密：…」 | ✅ 支付宝侧不涉微信支付分规范，但建议统一口径为「先享后付」 |
| `verify.vue` card-desc | 「推荐开通支付分 / 免密代扣；…」 | ⚠️ 「免密代扣」是支付宝侧术语，与微信侧混用，建议分开表述 |

### ③ 支付分开通成功 —— 弹窗

**结构**（成功态，居中弹窗或整页）：
1. 成功图标（品牌绿圆形对勾）
2. 主文案「**开通成功**」
3. 辅助文案「已开通免密支付，可直接开门」
4. **支付分标语**（原样复用官方素材，P13 颜色 `#07C160`）
5. 主按钮「去开门」/「返回首页」

**⛔ 禁止**：在标语周围添加任何文本（R2）——所以「已开通免密支付」**不能紧贴标语**，必须与标语保持明显间距或独立成块。

**回调时序对应**（本仓现状）：
- 用户在**微信支付分授权页**（`wx.openBusinessView` 拉起，微信侧页面）确认 → 微信回调 `authorization_code` + `USER_OPEN_SERVICE`
- ⇒ **③ 这一屏是「我方」页面，不是微信授权页**。微信授权页的截图由微信提供，交互图里只画我方页面。
- ⚠️ **必须在交互图中体现「跳转微信支付分授权页」这一步**：官方验收材料要求「用户扫码(含场景)→点击目标产品→授权支付分→授权成功→跳转详情页→成功」（服务商版《接入流程》2.4.1）。
  ⇒ 建议交互图第 ② 与 ③ 之间**插入一个「微信支付分授权页（微信侧）」占位框**，标注「微信支付分授权页由微信提供，此处为跳转目标」。

### ④ 扣款成功 —— 基本说明

**必备元素**：
| 元素 | 内容 | 本仓落点 |
|---|---|---|
| 逐件明细 | 商品名 × 数量 + 金额（**与 ① 同源同价**） | `order-detail.vue` 商品行 |
| 支付方式 | 「微信支付分」标签 | `order-detail.vue` 支付方式行 |
| 实付金额 | 精确到分 | 同上 |
| 申诉/退款入口 | 「有疑问可立即退款或提交申诉」 | **本仓已有**：`order-detail.vue:682-683`「关门自动扣款成功，如有疑问可立即退款或提交申诉」✅ |

**本仓现状**：`order-detail.vue:682` 已有该文案，**可直接复用**，仅需补「支付方式：微信支付分」标签行。

### ⑤ 订单完成页 —— 标签

| 元素 | 内容 |
|---|---|
| 主文案 | 「购物完成」/「结算完成」 |
| 本期合计 | 精确到分 |
| 支付方式 | 「微信支付分」标签 |
| 引导 | 「查看订单详情」 |

**⛔ 禁止**：不得在完成页出现「免密」「免确认」等词；不得引导用户再次授权（已是开通态）。

### 附 运营位（首页横幅，可选）

规范 P11：运营位 = 标题 + 按钮 + 结构。
- 标题：品牌标语原样（不可改字）
- 按钮：「立即开通」/「扫码开门」
- ⛔ 按钮**不得**写成「免密支付立即开通」

## 3. 交互图的制作与提交规范

### 3.1 官方硬要求（申请模板 §5）
> 「请将以上各环节流程页合并为一整张流程图片，示例如下」

⇒ **必须是 5 屏（或 6 屏，含微信授权页占位）横向或纵向拼接的**一张长图**，不是 5 张散图。

### 3.2 推荐制作方式（对齐微信侧验收）
服务商版《接入流程》2.4.1/2.4.2 要求：
- **场景使用流程-视频**【第三人称视角】：用户扫码(含场景)→点击目标产品→授权支付分→授权成功→跳转详情页→成功
  「视频内容需清晰展示实际产品/业务所在场景，成功后需验证消息通知」
- **产品体验流程-录屏**【第一人称视角】：①创建支付分订单：用户扫码→详情页面→确认页面→中间态→成功；②完结支付分订单：进行中→完结→完结成功
- **异常订单体验-录屏**：改金额（待支付→修改成功→扣款成功→完结→验证消息通知）/ 订单异常（创单或进行中→取消→取消成功→验证状态）

⇒ 🔴 **交互图与录屏必须一致**：图里画的中间态/成功态，录屏里必须真能复现。
本仓状态机：创单 `CREATED`（预授权未完成）/ `DOING`（进行中）/ `USER_PAYING`（待支付）/ `DONE`（已完结）
⇒ 交互图第 ③ 屏之后应体现 `DOING`，第 ④ 屏体现 `USER_PAYING → DONE`。

### 3.3 尺寸与构图建议
- 6 屏横向排列（微信授权页占位用虚线框 + 浅灰底 + 标注「微信支付分授权页（微信侧提供）」）
- 单屏按 375×812（@2x 750×1624）出图，屏与屏之间留 24px 间距 + 箭头 + 步骤序号
- 顶部一行标题：「微信支付分 · 无人零售（智能开门柜）先享后付 · 场景交互图」
- 底部一行落款：主体全称 + 场景名 + 日期
- ⚠️ **不可 PS 拼接后修改页面内容**；必须是真实页面的截图（或按规范 1:1 实现的原型）
