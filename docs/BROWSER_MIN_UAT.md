## 4. 层 B：单端浏览器抽检（18 条）

### 4.1 运营后台（8 条）

#### ADM-A01 正确登录 + redirect

1. 打开 `http://localhost/admin/index.html#/disputes`（未登录）
2. 期望：跳转 `#/login?redirect=...`
3. 输入 `13900000001` / `123456`，点登录
4. 期望：进入争议审核；面包屑/侧栏中文正常

#### ADM-A02 错误密码

1. 密码 `000000`，点登录
2. 期望：中文错误提示；停留登录页

#### ADM-A05 侧边栏分组/折叠

1. 点击「业务」「运营」分组 → 展开/手风琴
2. 底部「收起」或顶栏折叠 → 图标模式
3. 当前路由页菜单高亮

#### ADM-B03 设备列表

1. 进入设备管理 → 刷新、查询、重置
2. 点某设备进详情
3. 查：表格布局、中文设备名、按钮 loading

#### ADM-B08 争议审核

1. 需预置争议工单（可由 L-02 前置产生，或种子数据）
2. 打开详情 →「维持原账单」→ 二次确认
3. 查：弹窗层级、中文、结案后状态

#### ADM-B09 异常中心

1. 打开异常列表 → 筛选 OPEN
2. 详情 → 领取 → 转派（输入用户 ID）→ 填写处理结果 → 解决
3. 查：操作按钮、中文审计记录

#### ADM-B12 仓库采购（中文）

1. 仓库 → 新建采购单
2. SKU 选含中文商品名；数量、批次、效期填写
3. 创建后列表中文回显无乱码
4. 空 SKU 提交 → 表单校验提示

#### ADM-B14 灰度用户调余额

1. 灰度用户 → 选用户 → 调整余额 + 填写原因
2. 二次确认 → 余额变更
3. 查：金额 `¥` 格式、确认弹窗

### 4.2 消费者（6 条）

#### CON-C01 登录 + Tab

1. 打开消费者 H5 → 登录 `13800138000` / `123456`
2. 切换首页/订单/我的 Tab
3. 查：TabBar 底部安全区、无截获点击

#### CON-C03 开门购物

1. 首页手动输入 `CAB-001` → 确认开门
2. 查：全屏「门已开·购物中」；loading/disabled
3. 等待模拟器关门（或脚本 `set-simulator-cart.ps1` 预设）
4. 有 `lastDeviceId` 时验证「继续在本柜购物」卡片

#### CON-C05 结算订单

1. 结算后查看订单列表/详情
2. 期望：商品名、数量、金额、余额变化正确；中文正常

#### CON-C06 账单申诉（中文）

1. 订单详情 → 申诉
2. 理由填中文（页面内直接输入，非管道）
3. 提交成功；列表可见申诉态

#### CON-C07 余额不足

1. 将测试用户余额调至低于最低开门额（运营后台）
2. 消费者尝试开门
3. 期望：可读中文错误卡片，说明原因与下一步

#### CON-C09 故障报修

1. 购物页或首页 → 报修
2. 填写描述提交
3. 查：报修页布局、成功提示中文

### 4.3 商户（4 条）

#### MER-M01 四 Tab + 退出

1. 登录 `13800138001` → 概览/柜机/待办/我的
2. 退出登录 → 回登录页

#### MER-M03 柜机详情 + 温度

1. 柜机列表 → 进详情
2. 修改目标温度 → 保存
3. 查：成功/失败中文提示

#### MER-M05 补货任务

1. 补货任务（或 Tab 待办入口）→ 选 IN_PROGRESS 任务
2. 现场签到 → 确认商品 → 完成上架（逐步二次确认）
3. 查：底部 Sheet、步骤条、完成横幅

#### MER-M07 只读权限 403

1. 退出 → 登录 `13800138002`（只读店员）
2. 尝试改价或编辑货道
3. 期望：403 或「无权限」中文提示，非白屏

## 5. 层 C：跨端联调（10 条）

| ID | 流程 | 三端验证 | 重点维度 |
|----|------|----------|----------|
| L-01 | 正常购物 happy path | 消费者订单 = 运营订单 = 商户订单 | 金额中文 |
| L-02 | 申诉 → 运营维持 | 消费者工单结案；余额不变 | 提示文案 |
| L-03 | 申诉 → 运营免单 | 余额回退；运营异常同步关闭 | 二次确认 |
| L-04 | 报修 → 运营处理 | 异常 HIGH/DEVICE_FAULT 可见 | 中文标题 |
| L-05 | 运营调余额 → 消费者再开门 | 余额联动正确 | ¥ 格式 |
| L-06 | 商户低库存待办 → 柜机 | 跳转目标柜机正确 | 按钮可达 |
| L-07 | 采购收货 → 补货入柜 | 仓库库存↓ 柜机库存↑ | 中文 SKU |
| L-08 | Token 失效 | 三端各自跳转登录 + 中文提示 | 错误态 |
| L-09 | 购物中刷新恢复 | 刷新后会话态可恢复或明确提示 | 体验 |
| L-10 | 1366×768 快扫 | 三端无严重遮挡/横向溢出 | UI 设计 |

### L-01 详细步骤（联调种子）

1. `.\scripts\set-simulator-cart.ps1 -DeviceId CAB-001`（可选多商品）
2. 消费者开门 → 等待关门结算
3. 运营后台订单管理：核对 orderId、金额、商品行
4. 商户小程序订单：同一 orderId、金额一致
5. 截图三端订单页

### L-08 详细步骤

1. 任一端登录后，DevTools/Application 清除 token 或点退出
2. 触发需鉴权 API（刷新列表）
3. 期望：跳转登录页，提示会话失效（中文）
