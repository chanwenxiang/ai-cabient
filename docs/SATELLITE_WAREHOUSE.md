# 分仓补货落地（对照 easygo，小步）

> 来源：2026-10-04 会话（补货员与公司不在一地、仓在补货员附近）。  
> **不要**把商户要货当天作业入口；**不要**一次抄旧系统整包。

## 现场口径（easygo）

1. 仓跟人走：补货员/线长手机号绑一个分仓。
2. 采购进自己的仓：申请 → 审核 → 货送到该分仓。
3. 每天补柜不申请要货：缺货量 = 货道额定 − 当前库存；到柜开门改库存。
4. 月结：该仓应有 vs 实盘 vs 本月上柜件数。

## 推荐顺序（仍按此写，禁止并行铺开）

1. **人绑仓**：仓库 `manager_user_id`；后台编辑仓库时选择负责人。
2. **采购进分仓**：收货仓默认负责人的仓；无负责人则禁止当日常入口。
3. **日常从仓到柜**：缺货建议 → 出库 → 补货任务；无出库不「去补货」（闸门已在）。
4. **月结一张表**：应有 = 上期 + 采购入库 + 调入 − 调出 − 上柜 − 损耗；再对实盘。

要货只留给商户喊缺货，不是补货员每天入口。

## 保存约定（人绑仓）

- 后台编辑仓库会带 `managerUserId`：正数绑定，`0` 或清空下拉则解绑。
- CSV 导入不带该字段 → 后端当作「不改」，避免把已绑人冲掉。

## 保存约定（采购进分仓）

- 指定 `warehouseId`：仓必须存在且 `manager_user_id` 非空，否则中文错误拒绝。
- 不指定仓：取当前操作人作为负责人的第一家 `ACTIVE` 仓；没有则拒绝。**禁止**再落到无主默认中心仓。
- 后台新建采购下拉只列已绑负责人的仓；默认当前登录人的仓，否则当前筛选仓，再否则第一家有负责人的仓。
- 补货员小程序「采购入库」：`GET/POST /api/v2/merchant/satellite-purchase/*`，仓强制为当前人 `manager_user_id` 的 ACTIVE 仓；无仓拒绝。要货入口仍独立。
- 待收货单可在「单据」里确认收货（批次/到期日必填），库存入本人分仓；不能收别人的仓。

## 保存约定（日常从仓到柜）

- 规划补货路线生成出库：未指定仓时用柜机 `home_warehouse_id`；同一路线柜机必须同一所属仓。
- 仓必须已指定负责人，否则不能日常出库。**禁止**落到无主默认仓。
- 商户「缺货巡柜」只看缺口，不把要货当天作业入口；要货入口仍在柜机详情。
- 补货员日常采购走「采购入库」，不要货。

## 保存约定（月结一张表）

- 后台「库存与盘点 → 月结」：须选仓库和月份（上海时区）。
- 应有不含盘点调整；损耗单独列；实盘来自本月最近一次 COMPLETED/ADJUSTED 盘点。
- 只计件数，不写金额，不进结算 GMV。
