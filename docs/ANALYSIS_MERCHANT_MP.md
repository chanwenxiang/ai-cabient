## 四、用户角色与权限

### 4.1 商户角色
| 权限 | 说明 |
|------|------|
| 查看名下所有柜机 | 仅能查看绑定给自己的柜机 |
| 查看柜机经营数据 | 营收、订单、库存等 |
| 商品定价 | 设置柜机商品价格 |
| 查看争议订单 | 处理消费者争议 |
| 查看结算信息 | 收益统计、提现 |
| 分账设置 | 配置分账规则 |

### 4.2 补货员角色
| 权限 | 说明 |
|------|------|
| 查看分配的补货任务 | 接收补货工单 |
| 查看指定柜机信息 | 仅能查看需要补货的柜机 |
| 上报补货结果 | 完成补货任务 |
| 上报异常 | 设备故障等异常上报 |

### 4.3 权限隔离要求
| 要求 | 说明 |
|------|------|
| 数据隔离 | 商户只能看到自己的数据 |
| 操作隔离 | 补货员只能操作分配的任务 |
| 财务隔离 | 商户不能看到其他商户的财务数据 |

## 五、核心业务流程

### 5.1 补货流程
`
1. 系统生成补货任务（库存预警/定期补货）
2. 任务分配给补货员
3. 补货员到达柜机
4. 扫码验证/开门
5. 补货操作
6. 上报补货结果
7. 系统更新库存
`

### 5.2 争议处理流程
`
1. 消费者提交争议
2. 商户收到争议通知
3. 商户查看争议详情
4. 商户审核/处理
5. 同意退款/拒绝争议
6. 系统执行结果
`

### 5.3 结算流程
`
1. 订单完成后生成待结算金额
2. 达到结算周期/阈值
3. 系统生成结算单
4. 商户确认结算
5. 资金划转
`

## 七、权限隔离实现方案

### 7.1 后端权限校验
`java
// 商户只能查询自己名下的柜机
@PreAuthorize("hasRole('MERCHANT')")
public List<Device> getDevices(Long merchantId) {
    Long currentMerchantId = getCurrentMerchantId();
    if (!currentMerchantId.equals(merchantId)) {
        throw new AccessDeniedException("无权访问");
    }
    return deviceRepository.findByMerchantId(merchantId);
}
`

### 7.2 前端权限控制
`	ypescript
// 菜单根据角色显示
const menuByRole = {
  merchant: ['home', 'devices', 'pricing', 'business', 'disputes', 'settlements', 'revenue-share', 'alerts', 'mine'],
  replenisher: ['home', 'devices', 'replenishment', 'alerts', 'mine']
};
`

### 7.3 数据权限过滤
`sql
-- 商户只能看到自己的订单
SELECT * FROM orders WHERE device_id IN (
  SELECT id FROM devices WHERE merchant_id = :currentMerchantId
);
`
