# 运营后台查询与规范约定

## 一、日期查询默认值约定（统计类默认当天）

**规则：统计/报表类页面默认只查「当天」数据；只有用户明确选择日期（或 7/30/90 天档位）时才按所选范围查询。流水/待办类页面不适用，保持原有日期范围查询。**

### 适用（统计/报表类，默认当天）

| 页面 | 实现方式 |
|---|---|
| 设备可用性（KPI） | 默认当天实时口径；`?date=` 指定日期才查快照 |
| 数据分析 | 「今天」默认档（days=1），选 7/30/90 天才查对应范围 |
| 财务毛利 | 同上 |
| 销售报表 | 日期范围默认当天，选择范围才按范围查询 |

### 不适用（流水/待办类，保持原有查询）

订单、开门记录、对账、资金账单、充值、仓库出入库、争议审核、异常中心、审计日志——默认展示完整数据，由用户自行选择日期范围，避免漏历史、影响排查。

### 新增页面时的检查清单

1. 页面是统计/报表类 → 默认当天（单日期或 days=1）；是流水/待办类 → 保留日期范围；
2. 前端默认值不得向后端传"全量"语义（如空日期表示全部）——统计类默认必须显式传当天；
3. 后端接口默认值与前端一致（无参时返回当天，不返回全量）。

## 二、定时任务备注模板规范

定时任务「备注」用于说明这个任务干什么用的。**优先从用途模板中选择，再按实际情况微调**，统一措辞、便于检索与交接。

| 模板 | 填充文案 |
|---|---|
| 设备巡检 | 设备离线巡检、自动锁机/解锁，保障设备在线率 |
| 资金结算 | 资金类处理（分账/佣金/保证金等），涉及资金变动 |
| 对账 | 渠道对账与差异核对，确保账实一致 |
| 库存仓储 | 库存、临期、补货相关处理 |
| 交易订单 | 订单/会话/支付相关自动处理 |
| 营销优惠 | 优惠券/营销活动状态维护 |
| 运维监控 | 异常扫描、SLA、数据一致性巡检 |
| 其他 | 按需手写，说明触发条件与影响范围 |

备注建议包含：**做什么 + 触发条件/频率 + 影响范围**（例如：未付订单超时自动关单并回滚库存，涉及资金与库存）。

## 三、菜单/权限与侧边栏一致性（新增页面时必须遵守）

1. 侧边栏 `config/menu.ts` 的 path 必须与 `router/index.ts` 路由一致；
2. 数据库权限树：C 级菜单挂对应导航节点（如系统=403、设备商品=470），path 与前端路由一致；F 级按钮挂在 C 级权限下；
3. 页面 API 的 `@RequiresPermissions` 与菜单权限码一致；
4. 角色授权：跟随同类既有权限（如新增统计页跟随 ops:analytics:view / ops:device:list），admin 全量。
